Does Masking Always Help?

September 28, 2026 · Updated October 19, 2026
  • Editing

1. Masks in training-free T2I image editing

Training-free T2I image editing (image editing hereafter) takes a source prompt describing the original image, a source image to edit, and a target prompt describing the desired result. It uses these inputs to generate a target image that reflects the target prompt, without training.

In ordinary T2I inference, the task is to generate an image that matches the target prompt. In image editing, only the parts that differ between the source and target prompts should change; everything else should remain as it was in the source image. If I want to turn a lion into a tiger, but the zoo in the background also becomes a school, producing a tiger still misses the intended edit.

This is why image-editing evaluation also asks how well the background was preserved. Background PSNR, LPIPS, MSE, and SSIM measure this. Here, the background means the area outside the region to be edited, and these metrics measure the image differences between the source and target in that area.

Since inversion ODEs and FlowEdit, various approaches have tried to preserve the background, including methods that introduce masks. Using a mask is a fairly intuitive way to preserve it: specify the area to edit and keep the original outside it.

PIE-Bench, a major evaluation benchmark, already provides ground-truth (GT) masks of the edit region. To keep comparisons fair, methods cannot simply use these GT masks and instead obtain pseudo masks. Some use an MLLM and a segmentation model to locate the region to modify; others use differences in activations obtained through CFG.

Masking itself is not tied to a particular algorithm. The fact that one method uses a mask does not mean other methods cannot use one. This intuitive operation also translates into better scores. In the main quantitative result tables of papers that use masks, background PSNR, LPIPS, MSE, and SSIM are substantially better than those of methods without masks.

Using a mask is not inherently unfair, provided it is not the GT mask. Yet masking that could also be applied to other algorithms is left out of earlier methods when they are compared. I think presenting these earlier algorithms as relatively worse than masked methods, simply because they were published earlier, reduces the value of the information readers get from the comparison.

So in this post, I also apply masks to methods that originally did not use them and examine how their scores change.

2. Evaluation setup

Methods and data

I evaluated FTEdit, FlowEdit, FlowAlign, DNAEdit, and DirectEdit, the methods in the DirectEdit paper’s SD3.5 comparison. All used SD3.5-medium at 512×512 in fp16. I used the existing runners adapted from the official implementations for this setup, keeping each method’s hyperparameters the same with and without masking. Departures from the official runs are documented in the runner code and reproduction notes.

The initial evaluation used 151 PIE-Bench images sampled across edit types. To check whether the CLIP-whole decrease observed there also appeared in the remaining images, I expanded it to all 700 PIE-Bench images. Five methods, each run with and without a mask, produced 7,000 output images. This gives 3,500 paired comparisons of masked and unmasked outputs for the same source, across 700 original images.

Which mask, and how was it applied?

To compare the preservation operation without differences in automatic mask estimation, I gave every method the same PIE-Bench GT edit-region mask. This experiment does not evaluate how accurately a method finds the edit region in practice.

Applying a mask means pasting the source latent outside the mask immediately after each editing step’s update. A mask value of 1 keeps the edited latent; a value of 0 uses the source. The operation is applied element by element:

\[ z_{\mathrm{edit}} \leftarrow M \odot z_{\mathrm{edit}} + (1-M) \odot z_{\mathrm{source}} \]

\(M\) is the edit-region mask, and \(\odot\) denotes elementwise multiplication. Where the mask has a soft boundary, the two latents are mixed according to its value. This is the operation referred to as blending in this post.

The methods carry different latents through their iterations, so I defined the source to paste as follows.

Method Source latent pasted at each step Seed
FTEdit Source latent recorded during inversion at the corresponding timestep 2024
FlowEdit VAE-encoded original image 42
FlowAlign VAE-encoded original image 123
DNAEdit Source latent recorded during inversion at the corresponding timestep 0
DirectEdit Source latent recorded on the inversion/reconstruction path at the corresponding timestep 2024

FTEdit, DNAEdit, and DirectEdit use the source corresponding to the timestep. FlowEdit and FlowAlign use the same VAE-encoded source throughout the iterations. The no-mask condition omits only this pasting operation. Each method’s other mechanisms, including DirectEdit’s alignment and attention feature injection, remain enabled.

Mask preprocessing follows DirectEdit’s code. I expanded the edit region of the 512×512 GT mask by 3 pixels around its boundary, then resized it to the 64×64 latent resolution with bilinear interpolation. Every method received the same mask and preprocessing.

For 144 of the 700 images, the GT mask covers the entire image. There is no background to paste back in these cases. For the remaining 556 images, the mask covers only part of the image, and the source latent is pasted into the background outside it.

Metrics

I applied the original DirectEdit evaluator to all methods’ saved images. It extracts the edited 512×512 image on the right of each output file and compares it with the source image and target prompt.

Metric What it measures Better direction
Background PSNR, LPIPS, MSE, SSIM Difference between source and output outside the GT edit region Higher PSNR and SSIM; lower LPIPS and MSE
Structure Distance Change in the relationships between spatial locations, measured through DINO feature similarities over the whole image Lower
CLIP-whole Similarity between the whole output image and the full target prompt Higher
CLIP-edit Similarity between the output with only the GT edit region retained and the full target prompt Higher

The background metrics zero the GT edit region in both images before scoring them. PSNR and MSE use the whole image size as their denominator, rather than the number of background pixels. Structure measures preservation of the overall structure rather than directly judging whether an edit was completed. CLIP-edit also compares an image with everything outside the region blacked out against the full target sentence; it is not scored against a sentence describing only that region.

In the tables, Structure and LPIPS are scaled by \(10^3\), MSE by \(10^4\), and SSIM by \(10^2\). The background metrics are averaged over the 556 images with a background; Structure and both CLIP metrics use all 700 images.

Each method used one fixed seed per image. FTEdit and DirectEdit outputs were generated on an A6000; FlowEdit, FlowAlign, and DNAEdit outputs on an H100. Within each method, the masked and unmasked conditions used the same hardware and settings. All scores were computed on an A6000. The experiment did not cover other seeds, backbones, or automatic masks.

All five methods improved on the four background metrics and mean Structure Distance. Background PSNR rose by 11.37 dB for FTEdit, 10.62 dB for FlowEdit, 7.36 dB for FlowAlign, 8.23 dB for DNAEdit, and 8.87 dB for DirectEdit. FTEdit and FlowEdit, which originally did not use masks, both gained more than 10 dB from adding the same preservation operation.

The spread in mean background PSNR across methods narrowed from 4.15 dB without masking to 1.17 dB with it. Four methods, excluding FlowEdit, fell within 34.76–35.05 dB. Forcing the background to stay close to the source had a clear effect.

But the scores did not all improve together. Mean CLIP-whole fell for all five methods, with FlowAlign behaving differently from the other four in the distributions and confidence intervals below. CLIP-edit did not improve uniformly either. Better background preservation and changes in similarity to the target sentence need to be examined separately.

Among the 556 images whose masks cover only part of the image, 66.2–71.0% received a lower CLIP-whole score with masking in FTEdit, FlowEdit, DNAEdit, and DirectEdit. All four methods also showed a mean decrease on the remaining 549 images outside the initial 151.

FlowAlign had 297 decreases and 258 increases, a more even split. Its mean change of −0.177 points was also smaller than those of the other four methods.

The 99.5% confidence intervals, calculated by bootstrapping the per-image changes 20,000 times, were entirely below zero for those four methods. FlowAlign’s interval, [−0.383, +0.027], included zero.

How much of the mean decrease came from large drops?

Most of the mean decrease came from cases where CLIP-whole fell by more than 2 points. Depending on the method, these occurred in 76–143 of the 700 images. Removing them sharply reduced the mean decrease for the remaining images.

In the table, gross loss is the sum of the decreases across images whose scores fell. Net loss subtracts the gains from images whose scores rose.

Method Drops >2 points, out of 700 Share of gross loss Share of net loss Mean change after excluding these cases

DirectEdit 113 63.0% 81.2% −0.163

For FTEdit, FlowEdit, DNAEdit, and DirectEdit, drops greater than 2 points accounted for 81.2–91.1% of the net loss. Without these cases, the mean decrease was 0.087–0.163 points, much smaller than the full-set decrease of 0.531–0.858 points.

For FlowAlign, excluding the 76 drops greater than 2 points left a mean change of +0.275 points. Among the remaining images, gains outweighed losses. These gains offset the large drops, leaving an overall mean change of −0.177 points. This is why the large drops amount to 238.7% of the net loss.

The same pattern appeared across all 3,500 method–image pairs. The 517 pairs with drops greater than 2 points (14.8%) accounted for 64.2% of gross loss and 94.8% of net loss. Excluding them reduced the mean change from −0.588 to −0.036 points.

The five largest drops per method, 25 pairs in total, accounted for 7.3% of gross loss and 10.7% of net loss. The overall mean decrease was driven by 517 large drops across 256 original images.

4. FlowAlign: per-image normalization lowered background scores

FlowAlign’s official run_edit.py saves outputs with save_image(..., normalize=True). With no range specified, it maps each image’s minimum to 0 and maximum to 1. This conversion applies to the whole image, so background pixels preserved during editing are transformed again when the image is saved.

To measure the effect of the save policy, I reran the original 151 images without masking, using the same seeds and generation settings. One condition used a fixed input range of \([-1,1]\) for every image; the other normalized by each image’s minimum and maximum, as the official script does. Background metrics are averaged over the 120 images with a background.

FlowAlign save policy Structure ↓ bg-PSNR ↑ bg-LPIPS ↓ bg-MSE ↓ bg-SSIM ↑ CLIP-whole ↑ CLIP-edit ↑
Fixed input range \([-1,1]\) 13.26 27.32 45.44 26.85 91.30 26.66 22.67
Per-image min/max, the official save policy 36.11 24.81 53.39 45.66 88.47 26.60 22.59

Saving with per-image normalization made all four background metrics worse. Background PSNR fell by 2.51 dB, from 27.32 to 24.81 dB, while Structure Distance rose from 13.26 to 36.11. Only the save conversion changed; the generation settings stayed the same.

Keeping the other four methods’ results fixed and changing only FlowAlign’s save policy also moved its overall position, based on the average of its per-metric ranks in the original 151-image comparison, from first to third. In this post’s full 700-image comparison, both FlowAlign conditions use the fixed input range \([-1,1]\) for saving.
